# Фронтенд @Nonwire — передача команде

Реализована часть 1 из `quizblitz-project.md`: главная, гостевой вход, регистрация/вход, создание комнаты, лобби, приглашения по QR/ссылке, профиль и история. Игровые компоненты @karapuz1226 сохранены в `src/components/game`; новый `GameStage` подключает их после первого `question:show`.

## Запуск

Node.js 22+ и npm. Из папки `frontend`:

```sh
npm ci
npm run dev
```

Открыть адрес из терминала, обычно `http://localhost:5173`. На Mac можно запустить файл `Запустить QuizBlitz.command` в корне проекта. Исходный репозиторий: https://github.com/eco1kd/QuizBlitz. Готовая версия: https://github.com/lahmut-group/QuizBlitz (ветка `main`). Локальная рабочая ветка: `feature/nonwire-lobby`.

## Режимы подключения

По умолчанию работает самостоятельное демо. Скопировать `.env.example` в `.env.local` и перезапустить Vite, чтобы изменить настройки:

| Переменная | Значение | Назначение |
| --- | --- | --- |
| `VITE_GAME_MODE` | `mock` / `live` | Локальный игровой мок или существующий Socket.IO-сервер |
| `VITE_AUTH_MODE` | `demo` / `live` | Демо форм профиля или REST-авторизация |
| `VITE_BACKEND_URL` | `http://localhost:3001` | Адрес Socket.IO |
| `VITE_API_URL` | `http://localhost:8000` | Адрес REST без `/api`; пустой — текущий origin |

При обрыве связи live-режим **не переключается** на демо. Лобби остаётся на экране, действия блокируются, показывается состояние подключения и кнопка повторного соединения.

### Демонстрация без серверов

1. Нажать «Создать игру», ввести ник.
2. Выбрать тему, 3/5/10 вопросов, сложность.
3. Добавить демо-игроков в лобби или играть одному.
4. Начать викторину. После завершения результат появится в истории.
5. Проверить вход игрока: с главной ввести `849215`. В этом режиме нет кнопки ведущего.

Мок использует существующий банк вопросов о космосе/науке. Для 10 вопросов банк циклически повторяется. Тема и сложность — настройки для реального сервера; демо не изображает работу LLM. Демо-комнаты изолированы во вкладках, QR не обеспечивает мультиплеер без сервера.

Демо авторизации явно обозначено в формах. Регистрация/вход создают только локальное представление пользователя, не настоящий аккаунт. Пароли не сохраняются и не проверяются в демо. Сессия хранится в `sessionStorage`, завершённые демо-игры — в `localStorage` отдельно по пользователю. Логин в демо показывает UI, а не восстанавливает серверный аккаунт.

### Реальные комнаты с текущим бэкендом

В первом терминале, из `backend`:

```sh
npm ci
npm run dev
```

Во втором, из `frontend`:

```sh
VITE_GAME_MODE=live npm run dev -- --host 0.0.0.0
```

Авторизацию пока можно оставить `demo`: Node-сервер уже поддерживает комнаты, а REST-часть ещё не готова. Проверять роли лучше в двух браузерах/отдельных контекстах. Для игры с телефонов открывать Network URL Vite, и в `VITE_BACKEND_URL` указать LAN-IP компьютера (например `http://192.168.0.106:3001`, фактический адрес взять из сети). `localhost` на телефоне означает сам телефон. Устройства должны видеть оба порта. QR автоматически использует origin открытой страницы.

## Контракт с REST-частью @raikuchan

`src/services/account.ts` — единственная точка REST-интеграции. Пути соответствуют заданию. В задании не определены полные тела ответов; адаптер сейчас ожидает следующие формы — их нужно согласовать с бэкендом, а при необходимости поменять только адаптер.

```ts
// POST /api/auth/guest       body: { nickname }
// POST /api/auth/login       body: { email, password }
// POST /api/auth/register    body: { nickname, email, password }
// response:
{
  token: string,
  user: {
    id: string,
    nickname: string,
    avatar?: string,
    email?: string,
    isGuest: boolean
  }
}

// GET /api/me
{ id, nickname, avatar?, email?, isGuest }

// GET /api/games/history — массив:
[{ id, topic, playedAt, score, rank, players, questionCount }]
// playedAt: ISO 8601; score/rank/players/questionCount: number.
// Ошибка: HTTP 4xx/5xx, { message: string } или { detail: string }.
```

REST-запросы отправляют `Authorization: Bearer <token>`; Socket.IO получает токен через `auth.token`. Таймаут REST — 12 секунд. Ошибки не подменяются моковыми успешными ответами. Реальное истечение токена показывает ошибку с предложением войти снова. Выход очищает клиентскую сессию; endpoint серверного logout в задании отсутствует.

Генерация вопросов сейчас запускается **игровым сервером** в обработчике `game:start`. Фронтенд отправляет `room:create` с `{ topic, questionCount, difficulty }`, затем `game:start` с `{}`. Дополнительный запрос к `/api/questions/generate` не отправляется, чтобы не генерировать один набор дважды. Загрузка конспекта — бонус вне части 1/MVP; не добавлена.

## Socket.IO и восстановление

- События создания/входа ожидают подтверждение сервера; ошибки и таймаут не открывают фальшивое лобби.
- `room:updated` обновляет участников и определяет текущего игрока по `socketId` (расширение существующего сервера).
- Кнопка запуска видна только `roomInfo.isHost`; сервер также проверяет роль.
- Код, параметры комнаты и выданный сервером `playerId` сохраняются в `sessionStorage`. После реконнекта отправляется `room:join` с прежним `playerId`. Это сохраняет роль/очки и не создаёт новую комнату. Отдельные вкладки имеют независимые идентификаторы.
- Выход разрывает сокет, очищает сохранённую комнату и открывает чистое соединение. Специального `room:leave` в контракте нет.
- Игровые очки в live-режиме приходят с сервера; формула игрового мока осталась из существующего проекта.

### Известные ограничения текущего бэкенда

Эти места не исправлялись в чужой зоне ответственности:

1. `room:create` создаёт ведущего с ником «Хост» и аватаром 👑. Для персонального ника ведущего нужно использовать пользователя из токена либо согласовать расширение события.
2. При входе сервер присылает только список игроков. Тема/сложность/количество вопросов для вошедшего игрока неизвестны, поэтому лобби показывает «Игра с друзьями» без выдуманных параметров. Полный snapshot комнаты решит это.
3. После перезагрузки страницы на фазе вопроса сервер восстанавливает вопрос. На reveal нет полного вопроса, на leaderboard/finished нет полного snapshot. Для корректного восстановления **всех** игровых экранов нужен snapshot от бэкенда и обработка во второй части фронта. Лобби и идентификатор игрока восстанавливаются сейчас.
4. REST-авторизация/профиль/история отсутствуют в текущем checkout; live REST проверяется на уровне клиента, не заявлен как работающий энд-ту-энд с реальным REST-сервисом.

## UI-кит и структура

- `src/portal.css`: цветовые роли `--qb-*`, формы, скругления, сетки, адаптивные правила. Light Material 3 Expressive: тональные поверхности, крупная типографика, выразительные фигуры, pill-кнопки, пружинящие изменения формы. Шрифт Manrope с системным fallback.
- `src/components/portal/UI.tsx`: бренд, native-dialog с focus trap/Escape, декоративные SVG, формы.
- `Home`, `AuthDialog`, `CreateGame`, `RoomLobby`, `Account`: экраны части 1.
- `GameStage`: небольшой адаптер к неизменённым игровым компонентам части 2. Загружается отдельным JS-чанком.
- `useGameEngine`: один экземпляр состояния для лобби и игры. Подписки очищаются при unmount; live/mocks выбраны явно.
- `account.ts`: REST, демо-сессия и локальная история.

Управление доступно с клавиатуры; поля имеют label, ошибки — `role=alert`, состояния загрузки — `role=status`, есть skip-link. Native `<dialog>` удерживает фокус. Масштабирование страницы не запрещается; `prefers-reduced-motion` уменьшает CSS-анимации. Игровые экраны части 2 пока сохраняют собственную тёмную палитру.

Дизайн-ориентир: [Material 3 Expressive](https://m3.material.io/) и [Motion](https://m3.material.io/styles/motion).

## Проверки

```sh
npm run build
npm run test:e2e
```

Playwright на macOS использует установленный Google Chrome. На других системах предварительно выполнить `npx playwright install chromium`. Тесты проверяют создание комнаты, QR/копирование ссылки, неверный код, права игрока, валидацию ника, Escape, демо-регистрацию, отсутствие сохранения пароля, полный цикл демо-игры и историю, а также ширины 320/390/768/1440.

Для интеграционной проверки реального Socket.IO запустить backend и отдельный frontend:

```sh
VITE_GAME_MODE=live npm run dev -- --host 127.0.0.1 --port 5174
# В другом терминале, из frontend:
LIVE_E2E_URL=http://localhost:5174 npm run test:e2e
```

Live-тест использует два независимых браузерных контекста, проверяет общий список участников, отсутствие host-кнопки у гостя, сохранение кода/роли после перезагрузки и отключения сети, а также общий первый вопрос. Без `LIVE_E2E_URL` этот тест пропускается. Тесты ожидают default demo на порту 5173.
